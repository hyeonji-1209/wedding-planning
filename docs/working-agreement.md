# Working Agreement — 3인 AI-Native 팀

## 1. 사람에게는 결과를 배정한다

프론트/백엔드로 파일 영역을 나누지 않는다. 누구든 필요한 파일을 고친다.

| Owner | 책임 질문 | V0에서 소유하는 결과 |
|---|---|---|
| **Product / GTM** | 우리가 맞는 걸 만들고 있는가? | 첫 사용자 관찰, 범위 결정, 샵 시드 리스트, 브랜딩/랜딩 카피, 저작권 판단, 배포/획득 |
| **Experience** | 사람이 실제로 쓰고 좋아하는가? | 90초 내 스와이프 완주, 결과 화면의 "맞아요" 반응, 공유 카드 |
| **Intelligence / Platform** | 제품이 실제로 제대로 작동하는가? | 태깅 파이프라인, 매칭 품질, 골든셋 eval, 비용/안정성 |

경계에서 만나는 것 하나: **"왜 이 샵인지" 설명문.** Intelligence가 근거 데이터를, Experience가 표현을, Product가 그게 설득력 있는지를 판정한다. 셋 중 누구도 혼자 완성 못 한다 — 매주 리뷰의 고정 안건.

## 2. 하루 리듬

**만들어서 보여주는 게 물어보는 것보다 빠르다.** 물어볼지 만들지 고민되면 만든다 — 에이전트를 쓰는 팀에서 하루짜리 프로토타입은 검증 대상이 아니라 검증 도구다.


작업 시작 전에 슬랙에 두 줄만:

```
Outcome: 오늘 뭐를 되게 만들 건지 (기능 아님, 결과)
Touching: 건드릴 가능성 높은 영역
```

파일 ownership은 만들지 않는다. 겹치면 그때 말하면 된다.

main은 항상 동작. 작은 PR을 자주 merge. 리뷰 대기가 하루를 넘기면 그건 PR이 너무 큰 것이다.

## 3. 주간 리뷰

유일한 질문: **"이번 주 실제 사용자에게서 무엇을 새로 알게 됐나?"**
"무엇을 만들었나"는 안건이 아니다. 만든 걸 말하고 싶으면 그게 사용자에게서 뭘 알게 해줬는지와 함께 말한다.

## 4. 코딩 에이전트 사용 규칙

### 프롬프트는 목표·성공조건·제약으로

방법을 지정하지 않는다.

> 사용자가 고른 이미지로 취향 프로필을 만들고 결과 화면에 보여줘.
> 성공조건: 근거 썸네일이 속성마다 붙는다. 기존 테스트 유지 + 매칭 로직 테스트 추가.
> 제약: `lib/taste/vector.ts` 외부에 벡터 파생 로직을 만들지 마.

### 세션 위생 (토큰이 곧 속도다)

- **한 세션 = 한 Outcome.** 끝나면 `/clear`. 이전 작업 맥락을 다음 작업에 끌고 다니지 않는다.
- 세션 **시작할 때** `/model`, `/effort`를 정한다. 중간에 바꾸면 프롬프트 캐시가 깨져서 그 뒤 모든 턴이 비싸진다. fast mode 토글도 마찬가지.
- 파일은 경로를 타이핑하지 말고 **`@`로 붙인다** (Read 왕복 제거).
- 출력 많은 명령은 quiet 플래그. `pnpm test --reporter=dot`. 한 번 뱉은 로그는 남은 모든 턴에 실려 간다.
- 방금 한 실수는 `/compact` 말고 **`/rewind`** (캐시 유지, 공짜). `/compact`는 자리 비우기 직전이나 큰 방향 전환에만.
- 새 세션에서 `/context` 한 번 — 안 쓰는 MCP 서버나 CLAUDE.md 군더더기가 매 턴 실려 가고 있지 않은지 본다.
- 매일 쓰는 명령은 CLAUDE.md에 (이미 있다). 워크플로 지시는 skill로 — 쓸 때만 로드된다.

### 오케스트레이션

| 상황 | 방식 |
|---|---|
| 기본 | 메인 세션에서 직접. 대부분 이걸로 끝난다. |
| 출력이 시끄러운 조사 (전체 검색, 로그 뒤지기, 대량 파일 읽기) | **서브에이전트에 위임.** 결과만 돌아오고 로그는 안 돌아온다. |
| 구현 완료 후 | **다른 에이전트로 독립 리뷰.** Claude 구현 → Codex 리뷰 → 수정. 자기가 쓴 코드를 자기가 리뷰하면 자기 가정도 같이 통과시킨다. |
| 태깅 프롬프트/매칭 로직 변경 | `pnpm eval:taste` 통과 없이는 merge 금지. 사람 판단이 최종. |

**병렬 다중 에이전트 워크플로는 V0에서 안 쓴다.** 코드베이스가 3명이 머리에 담을 수 있는 크기다. 한 세션이 못 담는 규모가 되면 그때 도입한다.

### AI가 만들면 안 되는 것

- 제품 결정 (범위, 우선순위, 무엇을 안 만들지)
- 저작권/데이터 출처 판단
- "취향이 맞았다"는 판정 — 이건 사용자만 할 수 있다

에이전트가 이 영역에서 그럴듯한 답을 내놓으면 그건 답이 아니라 **Open Question**이다. `docs/kickoff.md`에 올린다.

## 5. 하네스 — 어떤 설정이 어디 사는가

3명이 같은 레포에서 에이전트를 돌리면 **공유해야 할 설정과 개인 설정이 갈린다.** 섞이면 남의 권한 설정이 내 세션에 딸려온다.

| 파일 | 커밋? | 뭘 넣나 |
|---|---|---|
| `CLAUDE.md` | ✅ | 매 세션 로드. **44줄 유지.** 명령어·스택·전 영역 공통 규칙만 |
| `.claude/rules/*.md` | ✅ | `paths:` 프론트매터로 **해당 파일 건드릴 때만 로드.** 영역별 규칙은 전부 여기 |
| `.claude/settings.json` | ✅ | 팀 공용 권한 allowlist·deny·훅 |
| `.claude/settings.local.json` | ❌ gitignore | 개인 권한 오버라이드, 내 머신 전용 |
| `CLAUDE.local.md` | ❌ gitignore | 개인 메모, 내 샌드박스 URL |
| `AGENTS.md` | ✅ (symlink) | `CLAUDE.md`를 가리킨다. Codex 리뷰 세션이 같은 규칙을 읽게 |

### CLAUDE.md에 `@import`를 쓰지 않는다
`@docs/foo.md`는 **세션 시작마다 전문이 로드된다.** 문서 5개를 임포트하면 1,000줄이 매 턴 실려 다닌다.
문서는 경로만 적어두고 필요할 때 읽게 한다. 항상 필요한 것만 CLAUDE.md 본문에 직접 쓴다.

### 규칙을 어디에 쓸지
```
매 세션 필요 + 전 영역        → CLAUDE.md
특정 디렉터리에서만 필요       → .claude/rules/*.md  (paths: 프론트매터)
여러 단계짜리 절차            → skill (호출할 때만 로드)
Claude 판단과 무관하게 강제    → .claude/settings.json 의 hooks / permissions.deny
```

마지막 줄이 핵심이다. **CLAUDE.md는 맥락이지 강제가 아니다.** "머지 전에 eval 돌려라"를 CLAUDE.md에 쓰면 지켜질 때도 있고 아닐 때도 있다. 진짜 막아야 하면 훅이나 deny 규칙으로 쓴다.

현재 강제되는 것 두 가지:
- `git push --force` 계열 **deny** — 3명이 공유하는 브랜치라
- `lib/taste/{prompt,vector}.ts` 또는 마이그레이션 수정 시 **PostToolUse 경고** — 회귀·충돌 1순위 지점

### 아직 안 만든 것
`.mcp.json`(공용 MCP 서버), 커스텀 skill, 커스텀 subagent. 필요해지면 그때. 지금은 세 명이 머리에 담기는 크기다.
