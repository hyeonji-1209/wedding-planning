# V0 Spec — Dress Taste Discovery

한 문장: **드레스 사진 25장을 넘기면, 내 취향을 언어로 설명해주고 그 취향에 맞는 국내 드레스샵 5곳을 근거와 함께 보여준다.**

검증할 가설: *사람들은 자기 시각적 취향을 언어화하지 못하고, AI가 그걸 대신 해주면 인스타 검색 대신 이걸 쓴다.*

---

## 1. 범위

### 만든다
| # | 화면 | 완료 조건 |
|---|---|---|
| 1 | 랜딩 | "웨딩 드레스 취향 테스트" 1스크롤, CTA 하나 |
| 2 | 취향 수집 | 드레스 이미지 25장 스와이프(♥/✕/저장). 90초 내 완료 가능 |
| 3 | 취향 결과 | 취향 이름 + Modern/Romantic/Classic/Bold %, 선호 속성 5개·기피 속성 3개, **각 속성마다 "네가 고른 이 사진 때문"** 근거 썸네일 |
| 4 | 샵 추천 | 매치율 순 5곳. 각 샵마다 매치 이유 3줄 + 내 취향과 닮은 포트폴리오 사진 3장 + 공식 링크 |
| 5 | 공유 카드 | MY WEDDING DNA OG 이미지 + 결과 영구 URL |

### 안 만든다 (V0)
가격 · 예약/상담 · 로그인(결과는 URL 토큰) · 스튜디오/메이크업/헤어 · 업체 대시보드 · 추천 개인화 학습 · 앱

### 데이터 규모 (V0 목표)
드레스샵 **30곳** × 포트폴리오 **20장** = **600장**. 이 이하면 추천이 뻔해지고, 이 이상은 V0에 불필요.

## 2. Taste Profile 스키마

이미지 1장 → 아래 구조로 태깅. 사용자 프로필은 ♥한 이미지들의 **평균 + 분산**, 기피는 ✕한 이미지에서 유의하게 높은 축.

```ts
type DressAttributes = {
  silhouette:    'a-line'|'ballgown'|'mermaid'|'sheath'|'empire'
  neckline:      'straight'|'v'|'sweetheart'|'halter'|'off-shoulder'|'high'
  fabric:        'silk-satin'|'crepe'|'tulle'|'lace'|'organza'|'mikado'
  sleeve:        'none'|'cap'|'long-sheer'|'puff'|'detachable'
  back:          'open'|'low-v'|'illusion'|'covered'
  tone:          'pure-white'|'ivory'|'champagne'
  embellishment: number  // 0=무장식 … 1=풀비즈
  volume:        number  // 0=바디컨 … 1=최대볼륨
  shine:         number  // 0=매트 … 1=글로시
  mood: { modern: number; romantic: number; classic: number; bold: number } // 합=1
  rationale: string      // 한 문장. 결과 화면 근거로 그대로 노출된다.
}
```

**`rationale`은 옵션이 아니다.** 이 필드가 곧 제품의 차별점이고, 없으면 그냥 점수 뱉는 앱이다.

매칭: 카테고리 축은 one-hot, 수치 축은 그대로 → 정규화된 벡터의 코사인 유사도.
샵 점수 = 그 샵 포트폴리오 상위 5장 유사도의 평균 (최고 1장만 쓰면 아웃라이어 1장으로 순위가 뒤집힌다).

## 3. 성공 기준 (V0 종료 판단)

베타 사용자 100명 기준. 이건 목표가 아니라 **계속할지 접을지 판단선**이다.

| 지표 | 계속 | 위험 |
|---|---|---|
| 25장 완주율 | ≥ 60% | < 40% → 수집 UX 실패 |
| 결과 화면 "맞아요" 응답 | ≥ 70% | < 50% → 태깅 품질 실패 |
| 추천 샵 외부 링크 클릭 | ≥ 40% | < 20% → 매칭이 안 믿긴다 |
| 결과 공유/저장 | ≥ 25% | < 10% → 바이럴 루프 없음 |
| 세션 후 인스타 복귀 (인터뷰) | — | 다수 → 핵심 학습 포인트 |

정량 지표가 다 통과해도 **"이거 플래너한테 보여주고 싶어요"가 인터뷰에서 안 나오면 V0는 실패**로 본다.

## 4. 검증 방식 — 물어보지 않고 관찰한다

첫 사용자는 **결혼 준비 중인 우리 직원**이다. 이미 있는 사람에게 3일 안에 만들어서 보여준다 (`docs/kickoff.md` Cut 1).

인터뷰 질문지는 만들지 않는다. 대신 제품 앞에서 관찰한다:

| 관찰 | 의미 |
|---|---|
| 25장 도중 이탈하는 지점 | 수집 UX가 지루해지는 정확한 장수 |
| 결과 화면에서 스크롤을 멈추는 곳 | 어떤 근거가 설득력 있는지 |
| **화면 옆에서 인스타를 여는 순간** | 제품이 못 하는 일이 뭔지. 가장 비싼 신호다 |
| 결과 URL을 누구에게 보내는가 | 공유 동기의 실체 (파트너? 친구? 플래너?) |
| 다음 날 링크를 다시 여는가 | 재방문. "쓸 것 같아요"보다 이게 데이터다 |

세션 후 딱 3개만 묻는다:
1. 이 결과에서 **틀린 것** 하나만 짚어주세요 (맞았냐고 묻지 않는다 — 예의상 맞다고 한다)
2. 지금 이 결과를 누구한테 보여주고 싶으세요?
3. 이거 없이 하던 걸 다시 한다면 뭐가 제일 아쉬울까요?

Cut 3에서 낯선 사람 100명으로 같은 걸 정량 계측한다 (§3).

## 5. 포지셔닝 (하지 말아야 할 것)

**"AI 웨딩플래너"라고 부르지 않는다.** 웨딩북이 2026년 그 이름으로 출시했고 스드메 확장을 예고했다. 그 단어를 쓰는 순간 우리는 후발 열위 제품이 된다.

우리 자리: **Wedding Taste Discovery.** 업체를 찾기 전에 취향부터 찾는 도구.
플래너를 대체한다고 말하지 않는다 — 플래너에게 취향 프로필을 넘겨주는 도구여야 업계 전체가 적이 되지 않는다.

기존 플랫폼과 안 겹치는 유일한 것: **왜 이 업체가 내 취향과 맞는지를 근거 사진과 함께 보여주는 것.** 이게 없으면 우리는 그냥 늦게 나온 웨딩 앱이다.
